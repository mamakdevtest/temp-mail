# MS Temp Mail — Client Source Audit (UI/UX v3 input)

## 1. `client/src/utils/apiFetch.js` (19 lines)

Exact contract:

- `unwrapEnvelope(payload)` — exported helper. If `payload.success === true` returns `payload.data`. If `success === false` returns `{ error: payload.error || 'internal_error', message: payload.message || payload.error || 'İstek başarısız' }`. If no `success` boolean (non-envelope), returns payload as-is. **Never throws** — it only reshapes.
- `apiFetch(input, init)` — exported. Calls `fetch(input, init)` and returns a `Proxy` of the `Response`. The only property it overrides is `.json()`: `async () => unwrapEnvelope(await readJson())`. All other props (`ok`, `status`, `headers`, `text`, etc.) pass through bound to the original `Response`.
- **No throwing, no 401/403 handling, no cancellation** (no AbortController). Callers must check `r.ok` / `r.status` themselves and call `r.json()` to get unwrapped data. Errors are only surfaced by throwing inside the caller (`throw new Error(d.error || '...')`).
- Re-exports `unwrapEnvelope` for components that need to unwrap raw `fetch` responses manually (AccountPanel, AdminPanel use this path).

### Implication
The 401/403 handling that does exist lives in two custom `request`/`apiRequest` wrappers (AccountPanel `request`, AdminPanel `apiRequest`), each reimplementing the same fetch + `unwrapEnvelope` + status logic. apiFetch itself is stateless and inert.

## 6. `AccountPanel.jsx` + `AccountEditorModal.jsx` — split of responsibility

### Why AccountPanel uses raw fetch + `unwrapEnvelope` instead of apiFetch
Look at its `request` helper (line 149-177). It needs behaviors apiFetch does not provide:
1. **Inject `Authorization` header** from `authToken` (passed via `auth?.token` prop) — apiFetch is a thin proxy and does not add headers.
2. **Handle 401 explicitly** — throws `'Oturum süreniz dolmuş, tekrar giriş yapın'` and lets caller show error (line 170-172).
3. **Stream a body** with conditional `Content-Type` (drops it when `options.json === false`, e.g. for `DELETE /auth/favorite-domains/:id`).
4. **Read body as text then parse** — works around empty 204 responses without crashing (line 160-168).
5. **Returns the already-unwrapped data directly** (not a Response proxy) so callers do `const d = await request(...)` without a second `await r.json()`.

apiFetch returns a Response-shaped Proxy whose `.json()` is async; AccountPanel wanted a plain async `request()` that returns data or throws. Hence it bypasses apiFetch but still reuses `unwrapEnvelope` for the envelope contract. Same reason AdminPanel's `apiRequest` (line 180-211) is a parallel reimplementation — both predate or avoid the Proxy-based apiFetch convenience. **This is a duplication hotspot: two near-identical wrappers of fetch + unwrapEnvelope + 401 handling.**

### `useImperativeHandle` (line 289-291)
```js
useImperativeHandle(ref, () => ({
  openSettings: () => openProfileEditor('genel'),
}));
```
AccountPanel is a `forwardRef`. App.jsx holds `accountPanelRef` and calls `accountPanelRef.current?.openSettings?.()` from `openAccountSettings` (App line 215-220) — triggered by the user menu "Hesap ayarları" button. The handle exposes exactly one method, `openSettings`, which opens the `<AccountEditorModal>` at the 'genel' tab. **Why:** the settings modal lives inside AccountPanel's state (`showProfileEditor`), but the trigger button lives in App's header user menu — so App needs an imperative way to reach across. This couples App to AccountPanel's internals via a ref.

### Split of responsibility
- **AccountPanel** (1390 lines, 20 useState, 5 useEffect) — owns: account summary card (guest + logged-in variants), recent/passworded history panels, its own `request` wrapper, `loadCenter` aggregator (`/auth/me` + `/auth/sessions` + `/auth/login-history` in parallel), `saveProfile/savePassword/savePreferences/requestEmailChange/confirmEmailChange/uploadAvatar/revokeSession/toggleFavoriteDomain/saveAddress/renewAddress/deleteAddress` actions, and the `center` state. Also owns `tab` state shared with the modal. Inline `<div className="hidden">` block (line 847-1335) is dead/legacy tab rendering kept in DOM but hidden — AccountEditorModal duplicates the same tabs.
- **AccountEditorModal** (898 lines, 2 useState, 3 useEffect) — pure presentational shell: sidebar nav, renders one of 6 tabs (`genel/profil/guvenlik/tercihler/oturumlar/kullanim` via `buildTabs(t)`). Owns only `avatarLoadError` and a `useEffect` to reset tab. All state and handlers are **passed as 35+ props** from AccountPanel. No fetch logic.

**Hotspot:** AccountPanel is itself a mini-god (1390 lines), and AccountEditorModal is a prop-drilling bridge with ~50 props. The "hidden" block inside AccountPanel (lines 847-1335) is duplicate dead UI.

## 9. State-quality findings (dedupe / server-state / modal-vs-route)

### Duplicate state that should be server state
- **`domains`** is fetched by App.jsx (`loadDomains` → `/api/addresses/domains`) and **also** by AdminPanel (`loadDomains` → `/admin/domains`) and by AdminBulkStudio (via `/api/admin/users` only, but receives `domains` prop from App). AccountPanel receives `domains` as a prop. AddressBar receives `domains` as a prop. There is no shared cache; each component that needs the full domain list either re-fetches or is prop-drilled.
- **`users`** is fetched by AdminPanel (`/admin/users`) and by AdminBulkStudio (`/admin/users`) independently — same endpoint, two unshared caches in the same admin session.
- **`bulkPools`** is fetched by AdminPanel (`/admin/bulk-pools`) and by AdminBulkStudio (`/admin/bulk-pools`) — same endpoint, two separate fetches when both views are visited.
- **`stats`** (admin) lives only in AdminPanel; **`stats`** (user) lives in useAuth. Different endpoints but conceptually same shape, both called `/auth/me` vs `/admin/stats`.
- **`emails`** in App.jsx vs `emails` in AdminPanel — App polls `/api/emails/:addr`, AdminPanel loads `/admin/emails?page&limit=50`. Different scopes; not a dedupe candidate but worth noting both keep their own paginated email array with no shared logic.
- **Auth preferences mirror**: AccountPanel holds `prefDraft` (theme/language/sound/notify_*) as a local draft copy of `auth.preferences`, then calls `auth.updatePreferences(payload)`. The `useEffect` at line 254-262 re-syncs `prefDraft` whenever `currentPrefs` changes — classic two-source-of-truth dance.
- **`notificationSound`**: stored in App.jsx `useState`, mirrored in `localStorage('tm-notification-sound')`, mirrored again in `auth.preferences.notification_sound` (saved by AccountPanel via `savePreferences`). Three places. The `handlePreviewNotificationSound` in App (line 209-213) writes both at once.

### Components re-fetching data App.jsx already has
- **AdminPanel** fetches `domains` itself via `/admin/domains` even though App already has `domains` from `/api/addresses/domains` — App does NOT pass `domains` to AdminPanel (App line 790-798 passes only `api, token, notificationSound, ...`). So AdminPanel re-fetches on mount (`refreshAll`).
- **AdminBulkStudio** receives `domains` from App as a prop (good), but re-fetches `users` that AdminPanel also fetches.
- **BulkStudio** receives `domains` from App as a prop — no duplicate fetch there.
- **AccountPanel** re-fetches `/auth/me` via `loadCenter` even though `useAuth.loadMe` already populated `user/pkg/stats/preferences` — and on every save action it calls `loadCenter` again to refresh (line 322, 400, 437, 466, 490, 503, 517, 531, 547). App's `auth` hook is the canonical source, AccountPanel's `center` is a parallel snapshot including `sessions`, `history`, `favorite_domains`, `addresses` (extra data not in useAuth).

## Complexity hotspots (for the roadmap)

1. **AdminPanel.jsx — 2456 lines, 40 useState, god component.** Owns 8 tabs + address-detail sub-route + DNS docs generator + subdomain manager + 2 modals + its own fetch wrapper. The single largest file.
2. **AccountPanel.jsx — 1390 lines, 20 useState.** Mini-god with its own fetch wrapper (`request`), parallel auth snapshot (`center`), dead hidden tab block (lines 847-1335), and 35-prop bridge to AccountEditorModal.
3. **App.jsx — 836 lines, 26 useState, 15 useEffect.** Hand-rolled router + socket + polling + backoff + 4 modals + toast + beep + address lifecycle. No state lifted to a store; everything prop-drilled.
4. **Two parallel fetch wrappers** (AccountPanel `request`, AdminPanel `apiRequest`) reimplementing apiFetch + unwrapEnvelope + 401 handling.
5. **AccountEditorModal — 898 lines, ~50 props**, pure prop-drilling shell.
6. **No server-state cache** — every list view re-fetches on mount; saves trigger full `loadCenter`/`loadUsers`/`loadDomains` re-fetches; duplicate `domains`/`users`/`bulkPools` fetches across admin views.
7. **All overlay state is component-local** — zero deep-linkable modals; AdminPanel address detail and BulkInbox are unreachable by URL.
